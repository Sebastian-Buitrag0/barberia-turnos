## 2024-05-28 - Missing Authorization on Admin Endpoints
**Vulnerability:** Several administrative endpoints (e.g., managing barbers in `UsuariosController`, manually registering turns in `TurnosController`) lacked `[Authorize(Roles = "Admin")]` attributes, allowing unauthenticated or under-privileged users to perform administrative actions.
**Learning:** In ASP.NET Core, controllers without class-level `[Authorize]` attributes leave their endpoints public by default. Developers must explicitly secure every sensitive endpoint to prevent Broken Access Control.
**Prevention:** Implement a secure-by-default approach by applying `[Authorize]` at the controller level or enforce authorization checks globally, then selectively use `[AllowAnonymous]` for public endpoints.

## 2024-05-28 - Missing Resource Ownership Authorization (IDOR)
**Vulnerability:** The `EnSilla` and `Finalizar` endpoints in `TurnosController` were protected by `[Authorize]` but lacked checks to verify that the authenticated user was the barber assigned to the turn. This allowed any authenticated user to modify the state and add services to any turn (IDOR). Additionally, CORS configuration had `.SetIsOriginAllowed(origin => true)` alongside `.AllowCredentials()`, creating a permissive configuration.
**Learning:** Method-level `[Authorize]` only verifies authentication and role. It does not automatically check resource ownership. When modifying specific resources (like a `Turno`), ownership must be explicitly validated within the controller logic. Also, permissive CORS configurations should be avoided.
**Prevention:** Implement explicit authorization checks in controller endpoints that modify resources. Extract the user ID from the claims (`User.FindFirst(ClaimTypes.NameIdentifier)`) and verify it matches the resource owner's ID, returning `Forbid()` if it doesn't.
