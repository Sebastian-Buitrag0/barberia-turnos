## 2024-05-28 - Missing Authorization on Admin Endpoints
**Vulnerability:** Several administrative endpoints (e.g., managing barbers in `UsuariosController`, manually registering turns in `TurnosController`) lacked `[Authorize(Roles = "Admin")]` attributes, allowing unauthenticated or under-privileged users to perform administrative actions.
**Learning:** In ASP.NET Core, controllers without class-level `[Authorize]` attributes leave their endpoints public by default. Developers must explicitly secure every sensitive endpoint to prevent Broken Access Control.
**Prevention:** Implement a secure-by-default approach by applying `[Authorize]` at the controller level or enforce authorization checks globally, then selectively use `[AllowAnonymous]` for public endpoints.

## 2024-05-28 - Missing Authorization on Read-Only API Endpoints Returning PII
**Vulnerability:** Read-only API endpoints (`GetTurnosHoy`, `GetCola`, `GetPorPagar`) returning data transfer objects (DTOs) that include Personally Identifiable Information (PII), such as customer phone numbers (`Cliente.Telefono`), lacked explicit authorization. This allowed unauthenticated users to enumerate the API and access sensitive data (Broken Access Control/Information Disclosure).
**Learning:** Just because an endpoint is read-only (GET) does not mean it is safe to expose. If the returned DTO contains PII or business-sensitive data, it must be protected with `[Authorize]` attributes that match the required access level of the intended consuming frontend view (e.g., Admin or Barbero).
**Prevention:** Always verify the data contract (DTO) returned by an API endpoint. If it contains PII (like phone numbers, emails, or names), apply `[Authorize]` explicitly, and use role-based restrictions (e.g., `[Authorize(Roles = "Admin")]`) when the data is only intended for administrative features.
