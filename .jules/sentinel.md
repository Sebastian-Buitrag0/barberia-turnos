## 2024-05-28 - Missing Authorization on Admin Endpoints
**Vulnerability:** Several administrative endpoints (e.g., managing barbers in `UsuariosController`, manually registering turns in `TurnosController`) lacked `[Authorize(Roles = "Admin")]` attributes, allowing unauthenticated or under-privileged users to perform administrative actions.
**Learning:** In ASP.NET Core, controllers without class-level `[Authorize]` attributes leave their endpoints public by default. Developers must explicitly secure every sensitive endpoint to prevent Broken Access Control.
**Prevention:** Implement a secure-by-default approach by applying `[Authorize]` at the controller level or enforce authorization checks globally, then selectively use `[AllowAnonymous]` for public endpoints.
## 2024-05-22 - [Insecure Direct Object Reference (IDOR) in TurnosController]
**Vulnerability:** The `EnSilla` and `Finalizar` endpoints in `TurnosController.cs` lacked resource ownership validation. Any authenticated user could send requests to these endpoints and modify turns belonging to other barbers by simply providing a valid `TurnoId`.
**Learning:** In ASP.NET Core MVC/Web API, controller actions protected by `[Authorize]` without roles will allow *any* authenticated user to invoke the action. Relying only on `[Authorize]` is insufficient if the resource being accessed/modified implies ownership (e.g., a specific barber managing their assigned turns).
**Prevention:** Always verify that the authenticated user matches the owner of the resource being accessed or modified (e.g., comparing `User.FindFirst(ClaimTypes.NameIdentifier)?.Value` to the resource's `BarberoId`), or that the user has elevated privileges (like the "Admin" role) explicitly allowing such modifications.
