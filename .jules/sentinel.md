## 2024-05-28 - Missing Authorization on Admin Endpoints
**Vulnerability:** Several administrative endpoints (e.g., managing barbers in `UsuariosController`, manually registering turns in `TurnosController`) lacked `[Authorize(Roles = "Admin")]` attributes, allowing unauthenticated or under-privileged users to perform administrative actions.
**Learning:** In ASP.NET Core, controllers without class-level `[Authorize]` attributes leave their endpoints public by default. Developers must explicitly secure every sensitive endpoint to prevent Broken Access Control.
**Prevention:** Implement a secure-by-default approach by applying `[Authorize]` at the controller level or enforce authorization checks globally, then selectively use `[AllowAnonymous]` for public endpoints.
## 2024-06-25 - Exposed Personally Identifiable Information (PII) in Turnos Endpoints\n**Vulnerability:** The endpoints `GetTurnosHoy`, `GetCola`, and `GetPorPagar` in `TurnosController` were completely public and returned `TurnoResponseDto`, which leaked the client's phone number (`Cliente.Telefono`) to unauthenticated users.\n**Learning:** Missing authorization on endpoints that return sensitive DTOs directly leads to data exposure. The frontend architecture safely allows us to protect these endpoints since only authenticated admin/barber views consume them.\n**Prevention:** Always verify the consumer of an API endpoint and apply the principle of least privilege using `[Authorize]` attributes. Never assume endpoints are safe to be public just because they read data rather than modifying it.
